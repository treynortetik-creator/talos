# Little Talos, 3D

An animated 3D build of the Talos mascot, rendered to 2D frames so the app can show him anywhere (transparent background).
Everything is generated by scripts. To change the model or a clip, edit the script and run the build again.

## One command

```bash
bash assets/mascot/3d/build.sh                 # model + rig + all clips -> talos.blend, frames, web assets, previews, contact sheet
CLIPS=idle,wave bash assets/mascot/3d/build.sh # just some clips
```

Needs Blender 5.x (headless), Python 3 with numpy, Pillow and scipy, ffmpeg (with libvpx-vp9) and `img2webp` (libwebp).
Optional: `PROOF=/path/to/proof.sh` for labelled preview MP4s; without it the previews are plain ffmpeg MP4s.
A full build takes a few minutes on an M-series Mac.

| file | what it is |
|---|---|
| `talos_build.py` | Blender script: builds the model, the rig and every clip action, saves `talos.blend`, renders the colour and ID passes |
| `talos_clips.py` | the clip library: one pose function per clip (pure Python, no Blender) |
| `talos.blend` | the saved scene: model, armature, one action per clip (fake-user), camera |
| `tools/finish.py` | composes the cream contours, downsamples, packs sprite sheets, animated WebP, WebM, previews and the contact sheet |
| `tools/score.py`, `tools/refmask.py`, `tools/critic_sheet.py`, `tools/round.sh` | the match-the-icon loop: silhouette IoU and part measurements against the brand icons, plus side-by-side boards for a critic |

## Method

The pipeline is a 3D-to-sprite pipeline: a rigged model, one fixed camera, flat materials and an ID pass for the part edges.

- **One fixed camera.** Orthographic, 10° down. Only the model moves. The model faces 12° to screen left, like the icon.
  It renders in EEVEE with a transparent film and Standard view transform, at 3x the cell size, then area-averages down.
- **Flat black-figure look.** All materials are emission-only (no lighting): black `#141110`, cream `#F3E6CF`,
  ichor `#FFB15C`, and emissive eyes, core and gear.
- **Cream part edges come from an ID pass.** Every part renders a second time in a unique flat colour.
  `finish.py` draws a cream line wherever two parts or the background meet, at that part's line width.
  That one mechanism gives the silhouette line, the bead separations, the eye rings and the rivet rings.
  An inverted-hull outline was tried first and dropped, because a hull only shows against things behind the part.
- **Incised panel lines are material lines.** Helmet chevron, ridge band, face seam, jaw, waist band and crest plates are
  plane-distance masks in each part's own object coordinates. The parts are rigid and bone-parented, so the lines ride the body through every pose ("lines hold").
- **Face features are drawn in icon pixels.** Eyes, smile, ^^ eyes, blush, brows, worried mouth, sweat drop and rivets
  are traced in the icon's pixel coordinates and projected onto the 3D surface through the render camera.
  From the render view they land where the icon has them.
- **Rig.** FK for the body plus analytic 2-bone IK for the arms and legs. Every frame is keyed into one action per clip.
  `eye_glow` and `core_glow` are custom properties on the armature that drive the emissive materials.
  Expressions switch with toggle bones (`face_n`, `face_h`, `face_w`, `sweat`, `hammer`).
- **Matched to the icon by iteration** (the photo-to-3d loop):
  1. Render three stills in the icon poses (pleased, beaming, worried).
  2. Measure silhouette IoU and the eye and core positions against the icons.
  3. A fresh critic that never saw the build compares side-by-side boards.
  4. Revise.

## Outputs

- `../frames/<clip>/0001.png...`: 512 px RGBA masters (build output, not committed).
- `../web/talos-<clip>-sheet.webp` + `.json` (build output, not committed): sprite sheet with frame size, count, fps, loop, `hold`, and `anchor` (the ground point).
  All clips share one crop, so clips can be swapped in place.
- `../web/talos-<clip>.webm` (VP9 + alpha, Chrome/Edge/Firefox) and `../web/talos-<clip>.mov` (HEVC + alpha, Safari): the lightest way to play a clip.
  Use `<video autoplay muted playsinline loop>` with both as `<source>`s, `.mov` first (`type="video/mp4; codecs=hvc1"`).
- `../web/talos-<clip>.webp`: animated WebP at 192 px, a fallback for `<img>`. `../web/sizes.json`: the size of every web asset.
- `../preview/talos-<clip>-preview.mp4`: each clip on terracotta, labelled.
- `../contact-sheet.png`: every clip, six frames each.

Web note: VP9-alpha WebM plays with transparency in Chrome, Edge and Firefox. Safari needs the HEVC `.mov` (VideoToolbox, so the `.mov` step needs macOS).

## How close it is to the icon

Six build rounds. Each round was judged by a fresh critic agent that never saw the build, comparing renders to the three icons side by side.
- **Silhouette IoU against the icons:** 0.77 (round 1) to 0.85-0.87 (final).
- **Eye and core centres:** within about 1% of figure height.
- **Critic verdicts:** "same character: no" in round 1, "yes" from round 2 on; "ship as-is: yes" in rounds 4 and 5.

The icon stills used for the loop are `ref-pleased`, `ref-beaming` and `ref-worried` in `talos_clips.py`. `bash tools/round.sh <dir>` renders them, scores them and writes the boards.

## Desktop companion atlases (C-ART, DESKTOP-COMPANION-SPEC section 9)

The same Talos, animated for the Mac desktop companion. No redesign: the model, rig, materials and proportions are untouched; the
new poses are new pose functions (`c_blink`, `c_walk_*`, `c_waiting`, `c_hammer`, `c_statue`, `c_landed`, `c_review`, `c_bust`) and
the `d_*` entries in `talos_clips.py`. The 8 web clips and 3 reference stills are not edited, and `assets/mascot/web` does not change.

```bash
python3 assets/mascot/3d/tools/atlas.py measure   # largest even 2x cell every pose fits (sets CELL2_RENDER)
python3 assets/mascot/3d/tools/atlas.py build     # renders, finishes and packs apps/desktop/Resources/companion/ (about a minute)
python3 assets/mascot/3d/tools/check_atlas.py     # spec 11.1 acceptance 1 and 3; exit 0 = pass
python3 assets/mascot/3d/tools/atlas_proof.py sheet <dir> <out.png> <photo.jpg>   # every state at 1:1 on white, black and a photo
python3 assets/mascot/3d/tools/atlas_proof.py real <dir> <out_dir> <photo.jpg>    # REAL-SIZE sheets (see below)
python3 -m unittest discover -s assets/mascot/3d/tools -p 'test_atlas.py'         # the unit tests; each one goes red on the art it guards
```

Python deps for the checks and tests: `pip install -r assets/mascot/3d/requirements.txt` (Pillow, numpy, scipy). The vitest wrapper
(`scripts/companion-art.test.ts`) runs them when the art changed or the deps are installed, and skips with a notice otherwise.

Needs the same tools as the web build (Blender 5.x, numpy, Pillow, scipy). `TALOS_DESKTOP=1` makes `talos_clips.CLIPS` include the
`d_*` clips; `atlas.py` sets it, and so does `build.sh` for the saved `talos.blend` (which carries every `d_*` action). A plain
`build.sh` still renders and packs only the 8 web clips; a partial `CLIPS=...` build leaves `talos.blend` alone.

| file | grid | cell | holds |
|---|---|---|---|
| `talos-2x.png`, `talos-1x.png` | 8x9 | 192x208, 96x104 | `idle`, `running-right`, `running-left`, `waving`, `jumping`, `failed`, `waiting`, `running`, `review` |
| `talos-ext-2x.png`, `-1x` | 8x3 | same | `talking`, `statue`, `landed` |
| `ember-2x.png`, `-1x` | 11x1 | same | eye and core glow alone, for the stepped opacity layer: one cell per clip that can hold still, cut from that clip's `still` pose (see below). **Amends the 1x1 row of spec 9.1** |
| `mini-2x.png`, `-1x` | 4x1 | 88, 44 | tondo busts: pleased, worried, waiting, statue (gear hidden, part lines 2.4x heavier, clipped to a circle with a cream ring) |
| `mini-ember-2x.png`, `-1x` | 4x1 | 88, 44 | the bust's eye and core glow, in the column of its state (`pleased`, `worried`, `waiting`; the statue's column is empty). **Amends the 1x1 row of spec 9.1** |
| `companion.json` | | | the manifest: per clip `atlas`, `row`, `frames` as `[column, ms]`, `loop`, `still` (the Reduce Motion column) |

Ember (spec 3.2), what a controller needs to know:
- Each clip that can hold still has `"ember": {"cell": k, "cols": [still]}` in `companion.json`. The layer is exact on the body only while the
  displayed column is in `cols`; show it only then (Idle: column 0, so it is off for the two blink frames; settled Working: column 7; Needs you:
  column 0, which `waiting` ends on; every Reduce Motion still). Statue has no ember: asleep, eyes dim.
- The layer is the glow drawn about 2x brighter than the glow baked into the body, so stepping its opacity from 0 to 1 moves the masked pixels
  by about 20/255 on average (eye colour goes orange to pale yellow). The first cut used the baked glow itself, which moved them by 2.5/255.
  Whether the steps read on a real panel at the chosen opacities is for C-PANEL to prove.
- `check_atlas.py` fails when a cell is more than 3% off the body's glow in its column, or steps by less than 15/255.
- `waiting` holds (loop false, ends on column 0): spec 2.2 says Needs you holds with ember, and ember runs only while no clip plays.

Real size: `atlas_proof.py real` writes `real-2x-<white|black|photo>.png` tagged 144 dpi (and `real-1x-*` at 72 dpi), each about 1200 px
wide, with the ember layer on and Mini at 44 pt. Open one in Preview at "Actual Size" on the Retina panel and one image point is one screen point.

Cell border at 1x: the spec says nothing opaque within 3 px of a cell edge. At 1x the anchor row is 100 of 104 and the stroke is 2 px, so a
planted sole ends 2 px from the bottom edge, and the spec's own numbers cannot give 3. `check_atlas.py` holds 1x to 2 px and prints that as a
named waiver line. The spec's acceptance text should say 2 px at 1x.

Facts a reader needs:
- `anchor` `[96, 200]` is in 2x pixels: the cell's horizontal centre and the row of the sole. The 1x anchor is half of it. Every frame
  except the two airborne hop frames (`jumping` columns 1-2; column 3 has landed, so Poke's four-frame hop ends on the ground) has its lowest foot on that row; the window is one fixed crop of the
  render for every clip, so a clip can be swapped for another in place.
- The cream outer line is a separate stroke at final size: 3 px at 2x, 2 px at 1x (1.5 pt and 2 pt). The part lines that come with the
  render are inside it.
- 1x is its own render at half the cell (`CELL2_RENDER / 2`), supersampled 4x. It is never a runtime scale of the 2x sheet.
- `running-right` and `running-left` are two renders with the figure turned each way. Nothing is mirrored (his arms differ).
- The `idle` row is three poses (open, half, closed) on a still body; its `frames` list holds the eyes open for 12 s between blinks. The
  breath and core pulse belong to the ember layer, not the body.
- `running` (one strike per 2 s) has no snap, head jerk, gear spin or eye flicker (the hammer takes 220 ms from the top pose to the strike); its last column is the settled pose and is its `still`.
- The Mini busts hide the gear and the rivets (the `hide` list of the `d_bust` clips, matched by object-name prefix; the build fails if it matches nothing).
- The Mini tondo is framed by `BUST_CENTER_Z` and `BUST_RADIUS_BU` in `tools/atlas.py` (3.45 and 2.25 BU; 3.30 and 1.86 cut the crest). `build_mini` measures the crest (`crest` and `crest_holder`, plus its part line) in the ID pass of every bust and fails the build when it reaches the inner ring, at 1x and 2x; `core_reach` does the same for the orange `core` (the outer bezel, `port_ring`, may still lose a pixel or two to the ring). The ring, corner and glow checks of `check_atlas.py` pass clipped art, so this guard is what protects the crest.
- Everything in `frames` is a hold table: ms is the time on that column, and a column may repeat.
- The palette is black `#141110`, cream `#F3E6CF` and the ember family (`#FFB15C` and the core and gear golds the model already uses).

## Idle antics (the desktop companion's `talos-life` sheet)

While he is idle and awake the desktop companion plays a gentle little thing every 1 to 3 minutes, so he never stands frozen.
All of it is pose and animation on the same model; the only new parts are two flat black Z letters (`zzz_a`, `zzz_b`, same cream contour
as every other part), hidden unless a pose shows them (a pose that does not name a Z has none, so every older clip renders as before).

| clip | cells | plays | what he does |
|---|---|---|---|
| `sit` | 7 | 7.0 s | sits down, legs out to the sides, swings his feet, glances aside, gets up |
| `nap` | 8 | 15.6 s | lies on his side with his arms tucked in, eyes shut and dim, core glow breathing slowly, Z's bob up and down, gets up |
| `stretch` | 7 | 3.9 s | arms up and out, head back, eyes squeezed shut in a wide grin (the beaming face), shakes it off |
| `scratch` | 7 | 4.4 s | looks left, looks right, scratches his head with his right clamp |
| `stumble` | 8 | 2.2 s | toe catches, windmills, catches himself, shakes his head |
| `tinker` | 8 | 4.2 s | takes out the hammer, holds it up and turns it over, gives it two light taps, puts it away |
| `sleep`, `wake`, `wake-low` | the nap's cells | 1.9 s, 1.5 s, 0.6 s | going to sleep is the lying-down half of the nap, waking is the getting-up (same row, a different hold table); `wake-low` gets up from the seated cell, for a wake that cuts the nap while he is still going down |

Every antic starts and ends on the idle stance (`tools/check_atlas.py` measures the silhouette overlap), so a clip cuts to Idle with no pop.
`talos-life-{1x,2x}.png` is 8 x 6 cells of the same size as the other sheets; the manifest's `atlases` block states the grid and the loader
reads it. The antics carry their own glow in the body, so they have no ember cell. `python3 tools/atlas.py build --only life --out DIR` renders
just this sheet (about 15 s) for looking at; the full build writes everything. `tools/life_sheet.py` makes the labelled contact sheets from frames
the real sprite view drew (`CompanionAnticGuiTests` with `TALOS_RENDER_OUT`).

## Idle life loops (the `talos-loops` sheet)

What the desktop companion shows all day instead of a frozen pose. These are posed through the rig (chest, shoulders, hips, arms,
head, eyes), never by sliding the picture: the root only moves a little over feet that stay planted (`stand` counter-offsets the
ankles, and `atlas.py` lifts each frame so the lowest foot sits on the anchor row).

| clip | plays | what he does |
|---|---|---|
| `idle-loop` | 4.0 s, loops (the Idle base) | breath in the chest and shoulders, a slow weight shift with the hips following, the arms hanging and swaying, the head drifting and tilting, one blink |
| `idle-look` | 5.0 s, once | the eyes lead, the head turns to screen left, holds, turns to screen right, holds, comes back; the body turns a few degrees |
| `needs-loop` | 4.0 s, loops (the Needs-you base) | rocks gently heel to toe, glances away and back to you, his free clamp drifts, one blink |
| `needs-beckon` | 3.0 s, once | looks right at you, nods, the free clamp curls toward himself twice |
| `needs-tap` | 3.0 s, once | glances down at his foot, a light toe tap, looks back up, one blink |

All five are authored at 24 fps and sampled to cells by `loop_cells` in `talos_clips.py`: a pose is held while the true motion stays within
`LOOP_TOL` (about a pixel at the shown size), never past a third of a second, so fast moments (a blink, a head turn) get many cells and slow
ones few. The sheet is one row per clip, `LOOP_COLS` wide; its grid is in `companion.json` like the others. The loops carry their own glow in
the body, so none has an ember cell. `python3 tools/atlas.py build --only loops --out DIR` renders just this sheet (about a minute).
`companion.json` is written in the committed layout (`dump_manifest`), so a rebuild changes only what changed.
